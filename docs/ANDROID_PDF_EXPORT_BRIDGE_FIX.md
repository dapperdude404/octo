# Android PDF Pages — Capacitor native bridge fix

## Reported failure

An Android screenshot of **PDF Pages → Images to PDF → Download PDF** shows:

```text
window.Capacitor.registerPlugin is not a function
```

## Root cause

`ai-octopus-v2/web/vendor-loader.js` used `window.Capacitor.registerPlugin('OctoDocument')`. The generated Capacitor Android WebView injects native plugin proxies under `window.Capacitor.Plugins`, but `registerPlugin` is normally imported from the `@capacitor/core` ESM package and is not guaranteed on `window.Capacitor`. The app uses unbundled browser ESM for its UI, so this invalid bridge call blocked PDF saving before the Android file picker opened.

The Java native document saver is already registered through `MainActivity.registerPlugin(OctoDocumentPlugin.class)`.

## Fix

- Use `window.Capacitor.Plugins.OctoDocument` first; a valid `window.Capacitor.registerPlugin` remains a compatibility fallback if present.
- Validate that native methods `begin`, `append`, `finish`, `discard` exist; show a specific actionable error when the plugin is unavailable.
- Preserve chunked save, 128-MB export cap, user cancellation and partial-file cleanup.
- Update the canonical `web/vendor-loader.js` and the `app/`, `docs/` and `online/` mirrors so all frontends remain in sync.
- Add Node regression tests for bridge-only Android runtime, PDF saved, cancelled, missing plugin, chunked data, error cleanup and compatibility fallback.

## Verification and remaining gate

- Run `cd ai-octopus-v2 && npm test && npm run web:check && npm run web:build`.
- Confirm GitHub **Android APK**, **Windows desktop** and **Docker/backend** workflows pass in the draft PR.
- Install the new **isolated debug APK** generated by the PR's Android workflow on a real phone; open **PDF Pages → Images to PDF**, select a JPG/PNG, tap **Download PDF**, select an Android destination, open the resulting PDF and inspect contents.
- Repeat **Document Studio → PDF export**, **PDF Pages → Combine files**, **Extract selected pages**, and cancellation.
- If an error remains, collect screenshot, OS/app version, and relevant WebView/ADB log. Automated JS tests and Gradle compilation alone do **not** establish physical Android save functionality.
